# Review checklist

A short checklist for anyone reviewing a pull request in this repo.

- [ ] The change is scoped to one concern
- [ ] Branch name follows the `feature/<short-description>` convention
- [ ] Commit messages follow the `type(scope): summary` style
- [ ] Tests or verification steps are included where relevant
- [ ] Docs are updated if behavior changed
- [ ] No secrets or credentials are present in the diff
- [ ] CI is green before merging
